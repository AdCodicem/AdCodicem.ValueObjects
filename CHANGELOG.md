## [0.3.0](https://github.com/AdCodicem/AdCodicem.ValueObjects/compare/v0.2.1...v0.3.0) (2026-10-29)

### ⚠ BREAKING CHANGES

* AdCodicem.ValueObjects.Marten, .Wolverine.Http, .HotChocolate.Data, .Orleans,
.CommandLine and .CsvHelper are no longer published; their previews stay on nuget.org, deprecated.
VO0048 is gone.

Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
* **efcore:** under ConfigureValueObjects, an entity whose primary key is a single Guid value object that nothing
generates is refused with an InvalidOperationException carrying value_object.required when it is added, attached,
updated or removed with its key unset, or found unset through a navigation, rather than stored with Guid.Empty;
HasData can no longer seed such a key with Guid.Empty. A key whose type refuses Guid.Empty is now refused there, at
Add, with that exception, rather than at SaveChanges with a DbUpdateException around a ValueObjectException; both carry
value_object.required, which ValueObjectErrors.TryGetCode reads. Attach or Update of an aggregate whose dependent's key
holds a foreign key to such a key, left at its default for the navigation to fill in, a dependent sharing its
principal's key or one keyed by its principal's key and a number, now tracks that dependent as added, as for a Guid
key, where it was tracked unchanged: set its foreign key, or its state, by hand. Assign the key, generate it with
HasValueObjectKeyGeneration(), or opt the key out with ValueGeneratedNever().
* declare known values and the example as typed members
