# AdCodicem.ValueObjects docs site

The [documentation site](https://adcodicem.github.io/AdCodicem.ValueObjects/), built with
[Docusaurus](https://docusaurus.io/). Content lives in `docs/`; the sidebar order is explicit in `sidebars.ts`.

```bash
npm ci
npm run docs:api    # generate docs/api/ from the XML doc comments in ../src (needs the .NET SDK)
npm start           # local dev server with hot reload
npm run build       # production build; fails on a broken internal link
npm run serve       # serve the production build locally
npm run typecheck   # TypeScript, no emit
```

`npm run docs:api` is a prerequisite for the other two, not an optional extra: the API reference under
`docs/api/` is generated by DocFX from the source and is **not** committed, while `sidebars.ts` builds its
`API reference` category from that directory. Without it, both `npm start` and `npm run build` fail on a
sidebar pointing at nothing. It only needs re-running when a public signature or an XML doc comment changes.

Two things about that generated output are worth knowing if you touch the pipeline:

- `markdown.format` is `'detect'` in `docusaurus.config.ts`, so `.md` is parsed as CommonMark rather than MDX.
  The generated pages are full of bare generic signatures like `ValueObjectContract<TValueObject, TValue>`,
  which MDX would try to parse as JSX and reject. No hand-written page uses MDX features.
- `.github/scripts/docfx-postprocess.py` rewrites DocFX's raw `<a id="...">` heading anchors into Docusaurus
  heading ids. Without it Docusaurus nests its own anchor inside DocFX's, which is invalid HTML and produces
  several hundred minifier diagnostics.

Deployment is automatic: `.github/workflows/deploy-docs.yml` builds and publishes this site to GitHub Pages on
every push to `main` that touches this directory, and is also called by `release.yml` after a stable
release so the published site never describes an older version than nuget.org. There is no `deploy` script here — the site is not pushed to
a `gh-pages` branch by hand.
