Has the database generate the key when an entity is added: an identity column on SQL Server and PostgreSQL, the
row identifier on SQLite, with a temporary value in the change tracker until the row is saved.

#### Remarks

<p>
The key becomes generated on add, as an <xref href="System.Int32" data-throw-if-not-resolved="false"></xref> key is by convention, and gets the generator of
<xref href="AdCodicem.ValueObjects.EntityFrameworkCore.ValueObjectKeyGeneratorFactory%602" data-throw-if-not-resolved="false"></xref>, which a compiled model can write. The column becomes
an <code>IDENTITY</code> on SQL Server, a <code>GENERATED BY DEFAULT AS IDENTITY</code> on PostgreSQL, and stays an
<code>INTEGER PRIMARY KEY</code>, the row identifier, on SQLite, which reuses the highest key once it is deleted unless
the property also calls SQLite's <code>UseAutoincrement()</code>: unlike a key of the <xref href="System.Int32" data-throw-if-not-resolved="false"></xref> itself, which
is <code>AUTOINCREMENT</code> there by convention.
</p>
<p>
Until <code>SaveChanges</code>, the change tracker holds a temporary value, negative and never written, and the
entity's property its default; the key the database generates then takes its place, read through the converter,
so a type counted from one accepts it, in a strict context too. Zero, the default, is generated over; any other
key the domain set is kept, which SQL Server then refuses to insert into an identity column, and PostgreSQL
stores. Only a relational database generates the key: on another provider, Entity Framework Core's in-memory
database for one, adding an entity without its key throws an <xref href="System.InvalidOperationException" data-throw-if-not-resolved="false"></xref>, rather
than store the temporary value as the key.
</p>
<p>
SQL Server cannot alter an existing column into an identity column: a migration from a model where the key was
not generated fails, and the table has to be created again. On PostgreSQL, such a migration starts the identity
at one, below the keys the table already holds.
</p>
